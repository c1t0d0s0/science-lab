# 理科ラボ

小学生のための理科の実験シミュレーターです。条件を選び、結果を予想して、実験でたしかめます。ブラウザだけで、PC・タブレット・スマートフォンのどれでも遊べます。

- **学年ごとに、考え方をステップアップ** (学習指導要領解説の「問題解決の力」をもとにしています)
  | 学年 | モード | 思考の目標 | 画面 |
  |---|---|---|---|
  | 1・2 年 | はっけん | 違いを見つける、結果を予想する | ひらがな中心・ボタン操作中心 |
  | 3・4 年 | くらべる | 2 つの条件や結果を比べ、共通点を見つける | A と B の 2 つの実験を並べて同時に行う |
  | 5 年 | 条件をそろえる | 1 つの条件だけを変え、ほかをそろえて調べる | 2 つ以上の条件を変えるとハカセが注意。そろえた実験だけを数える |
  | 6 年 | 仮説・検証 | データを根拠に、結論がどこまで妥当かを判断する | 測定にばらつきがあり、同じ条件で何回かはかって平均。結論の妥当性をえらぶ |
- **15 の実験・49 のミッション** (`src/experiments/`)
  - 1・2 年: 磁石につくもの / うくもの・しずむもの / ライトとかげ / 風で動く車
  - 3・4 年: 磁石と金ぞく / 太陽とかげ / かがみと日光 / 風・ゴムで動く車 / 電気の通り道 (直列・へい列は 4 年) / 水をあたためる (4 年)
  - 5 年: ふりこのきまり / 水の温度変化 / 発芽と成長 / 電磁石の強さ
  - 6 年: てこのきまり / 水よう液のなかま分け / 月と太陽 / 複数回の測定 (ふりこ・電磁石の 6 年版)
- **予想と結果の比較**: 実験の前に予想 (3 年からは理由も) を保存し、実験のあとで予想と結果を比べ、「実験のあとの考え」と、考えを変えた (変えなかった) 理由をふりかえります
- **実験データの自動グラフ化**: 実験するたびに条件と結果を表に記録し、調べた条件を横じくにしたグラフにします。6 年生むけは 1 回ずつの点と平均を分けて表示。5・6 年生むけは前の実験から変えた条件に印がつきます
- **自由研究モード**: 調べる条件を自分で選び、予想し、実験して、記録から「わかったこと」を選んでノートにまとめます。選んだ結論が記録と合っているかは、データの傾向から判定します (`src/core/lab.ts` の `trend`)
- **学年別のヒント**: 柴犬のハカセが、低学年には「どっちが おおきいかな？」、高学年には「ほかの条件は そろえた？」「1回だけで決めていいかな？」と、同じ実験でも支援の仕方を変えて声をかけます
- **今日のチャレンジ**: 日本時間の日付と学年から、その日のミッションが 1 つ決まります (どの端末でも同じ)。1 回りで全部のミッションが出て、2 日つづけて同じものは出ません
- **スタンプカードと柴犬カード**: 今日のチャレンジをやりとげるとスタンプとポイント。ためたポイントで柴犬カード (20 種類) と交換できます
- **実験ノート**: やりとげたミッションと自由研究の記録 (予想・理由・わかったこと・ふりかえり・実験の記録) が残ります (新しいほうから 60 ページ)
- 図とアニメーションは、すべてその場で SVG としてかきます (画像ファイルは使いません)。暗い画面の設定では黒板のような色になり、「視差効果を減らす」設定ではアニメーションを省きます

## 動かし方

```sh
npm install
npm run dev      # 開発サーバー
npm test         # テスト
npm run build    # dist/ に公開用のファイルを作る
npm run preview  # dist/ の中身を手元で見る
```

開発サーバーでは `gallery.html` で、全部の実験の条件ごとの図と柴犬カードを一覧できます (`?exp=pendulum` で 1 つだけ)。ビルドには入りません。

## ポイント

| もらえるとき | ポイント |
|---|---|
| 今日のチャレンジをやりとげる (学年ごと・1 日 1 回) | 20pt |
| その予想が当たっていた | さらに 10pt |
| ミッションをはじめてクリア (ミッションごとに 1 回) | 10pt (予想が当たれば +5pt) |
| 自由研究をノートにまとめる (1 日 1 回) | 10pt |
| スタンプが 7 日つづくたび | 1,000pt |
| その月の 1 日から末日まで、スタンプが全部そろう | 5,000pt |

- スタンプは 1 日 1 個。どれかの学年の今日のチャレンジをやりとげた日に押されます
- スタンプもポイントも、保存してある記録から毎回計算します (`src/core/rewards.ts`, `src/core/storage.ts`)。合計は保存しないので、ずれたり二重にもらったりしません

## Google のタグ

ビルドのときに、環境変数 `GTM_ID`、なければプロジェクト直下の `config.js` (`config.example.js` を参照) の `GTM_ID` を読んで、
`index.html` に Google のタグを埋めこみます (`GTM-…` なら タグ マネージャー、`G-…` なら Google アナリティクス)。どちらもなければ埋めこみません。`config.js` は Git で管理しません。

GitHub Pages に公開するときは、リポジトリの変数 `GTM_ID` に ID を入れてください (`.github/workflows/deploy.yml`)。

## ログインと記録の保存 (Firebase)

まいにち理科ノート (science-quiz) と同じしくみです。Google でログインした人の記録は Firestore に保存し、ログインしない人はそのブラウザの localStorage だけに保存します。
**Firebase の設定を入れていないビルドでは、ログインの入り口は出ず、Firebase のコードも読みこまれません。**

- 画面はいつも手元 (localStorage) の記録を読み書きし (`src/core/storage.ts`)、ログイン中は書きかわった分を少しまとめて Firestore に送ります (`src/cloud/sync.ts`)
- 2 か所の記録の合わせ方は `src/core/merge.ts` にあり、何回合わせても同じ結果になります

  | 記録 | 合わせ方 |
  |---|---|
  | 今日のチャレンジ・自由研究・クリアしたミッション | 両方を合わせる。同じものは、予想も当たったほう |
  | その日の途中経過 (予想・ふりかえり) | 先まで進んでいるほう。同じところまでなら、あとから保存したほう |
  | 柴犬カード | 両方を合わせる (同じカードは払った額の小さいほう) |
  | 実験ノート | 両方を合わせる。同じページは、あとから書いたほう。新しいほうから 60 ページ |

- 手元の記録は人ごとに分けます。ログインなしは `science-lab:v1:…`、ログイン中の人の写しは `science-lab:u:<uid>:…`。ログアウトすると、その人の写しは端末から消します
- ミッションの途中の実験の記録 (表とグラフ) は、そのタブの sessionStorage にだけ置きます (やりとげるとノートに入ります)

### Firestore の形

記録は `users/{uid}/apps/science-lab` の下に入ります。まいにち理科ノートと同じ Firebase プロジェクトを使っても、記録はまざりません。
ルールは `firestore.rules` にあります (読み書きできるのはログインしている本人だけ)。

```
users/{uid}                                          その人の情報 (全アプリ共通)。名前・メールアドレスは保存しない
users/{uid}/apps/science-lab                         記録のまとめ
  activeDays: string[]                               どれかの学年の今日のチャレンジをやりとげた日
  completed:  string[]                               「レベル:日付」(g5:2026-10-20) と「free:日付」
  inventory:  { l01: { paid: 40 } }                  持っている柴犬カードと、交換に使ったポイント
  settings:   { scores: { "g5:2026-10-20": 2 },      1: やりとげた / 2: 予想も当たった
                cleared: { "pendulum-mass": 1 },     クリアしたミッション
                notes: [...] }                       実験ノート
users/{uid}/apps/science-lab/progress/{日付:ミッション}  その日の途中経過 (前の日までのものは消す)
  data: { sig, answers }                             ミッションの印と、[予想, 理由, 実験のあとの考え, その理由]
```

### 設定

次の 4 つの値を入れます。4 つのうち一部だけを入れると、ビルドがエラーになります。

- 手元: `config.js` に `FIREBASE_API_KEY` `FIREBASE_AUTH_DOMAIN` `FIREBASE_PROJECT_ID` `FIREBASE_APP_ID` を書く (書き方は `GTM_ID` と同じ)
- GitHub Pages: リポジトリの Settings → Secrets and variables → Actions → Variables に、同じ 4 つの名前で登録する
- 公開先のドメインを、Firebase コンソールの Authentication → 設定 → 承認済みドメイン に足しておく

### エミュレーターで動かす (開発用)

```sh
npx firebase-tools emulators:start --only auth,firestore --project demo-science-lab
FIREBASE_API_KEY=x FIREBASE_AUTH_DOMAIN=localhost FIREBASE_PROJECT_ID=demo-science-lab FIREBASE_APP_ID=x FIREBASE_EMULATOR=1 npm run dev
```

ブラウザのコンソールで `window.__testUser = 'kid1'` としてからログインのボタンをおします。

### ミッションを足すには

実験のファイルの `…Missions` にミッションを足します。

```ts
{
  id: 'pendulum-length',          // ほかと重ならない名前
  exp: 'pendulum',
  levels: grades(5),              // 出す学年
  question: 'ふりこの長(なが)さを変えると、1往復(おうふく)する時間は？',  // 「漢字(よみ)」でふりがな
  choices: ['長いほど長くなる', '長いほど短くなる', '変わらない'],
  answer: 0,
  target: 'length',               // 調べる条件
  need: { key: 'length', distinct: 3 },  // 何通りためしたら まとめられるか (5・6 年は条件をそろえた実験だけ数える)
  finding: '…',                   // わかったこと
}
```

`need` には `among` (この値だけ数える)、`where` (この条件の実験だけ)、`repeat` (同じ条件で何回ずつ)、`result` (この結果の実験だけ)、`fair: false` (条件をいくつ変えてもよい) が使えます。
6 年生むけには `noise: true` (はかるたびにばらつく) と、`conclusions` (データから言えることの選択肢。正しいものを 1 つ) をつけられます。
`npm test` で、ミッションの形と、調べる条件だけを変えて実験すればやりとげられることを確かめます。
